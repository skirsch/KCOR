# Objection 3: the method stated in the paper

This folder evaluates the manuscript's stated algorithm separately from the tested production code and from the exploratory exact conditional joint-fit candidate. It starts with the component that the paper specifies precisely: Step 1 jointly fits baseline scale and frailty by least squares in the nearest quiet window.

**Main result:** With the paper's joint fit held fixed on **the same 200 model-consistent datasets**, 95% intervals covered **189/200 (94.5%)** using the software's person-resampling Monte Carlo and **38/200 (19%)** using one explicit four-week aggregate-block rule; [paired assessment](paired_resampling/ASSESSMENT.md). The paper's joint point fit is nearly exact on model-expected counts. Its written aggregate-block interval is not uniquely defined by the manuscript, so the 19% result belongs to the chosen block-placement and seam rules. The [exact-count and placement audit](block_bootstrap_operationalization/WHY_BLOCK_PLACEMENT_MATTERS.md) shows why these choices matter. The production fitter also differs from the paper's joint fit, so the 94.5% figure is not coverage for the complete current production pipeline.

## Deterministic Step 1 check

The paper's predictor is `k*exp(gamma*t)/(1+theta*H_gom(t))`, with `H_gom(t)=k*expm1(gamma*t)/gamma`. [paper_step1.py](paper_step1.py) implements that two-parameter least-squares objective literally. The check uses the same model-consistent unequal-frailty generating population as the objection 3 study, weeks 6–40 as the one quiet window, two skipped weeks, and the paper's exact cumulative gamma inversion after fitting. It repeats the optimization from four frailty starting values per arm.

On exact expected counts, the true normalized contrast is 1; this paper Step 1 fit gives **0.9999999663**. It estimates frailties **4.00000154 and 0.50000005**, with fitted rebased baseline scales **0.0009901195 and 0.0009987540**. These baseline scales need not equal the original-enrollment generating scale of 0.001 because the fit begins after deaths in the skipped weeks. The [retained result](exact_population.json) includes starts, objective values, source hashes, and parameters. It demonstrates that the deterministic 1.00461455 offset found in the current fixed-rate code does **not** carry over to this explicitly written one-window joint Step 1.

This check is not a full reproduction of the manuscript's multi-window estimator, diagnostic gate, or uncertainty intervals. In a one-window scenario there are no between-window offsets to estimate. The paper's Step 4 says to refit frailty across the union of quiet windows with baseline scale fixed. Whether that includes the initial non-quiet anchor weeks used by current code is a separate specification choice; this check uses only the paper's named quiet-window objective.

## The paper's interval procedure needs an operational definition

Section 2.9.1 says to resample contiguous blocks of event-time bins within each cohort and stratum, rebuild the risk sets sequentially, repeat fitting, and take percentile endpoints. The text and supplement do not specify a block length or rule for choosing it, how a sampled block is assigned to the follow-up timeline, or how risk sets are joined at boundaries between independently selected blocks. These choices affect the distribution of the resulting intervals. The supplement says individual records are not resampled. The repository's real-data Monte Carlo code instead resamples people; the simulation-grid script makes approximate weekly Poisson death draws. The [interval-provenance audit](../objection3_step2_interval_provenance_2026-11-10/assessment.txt) traces these distinct paths and does not attribute historical manuscript intervals to one without source evidence.

Consequently, **the paper's exact percentile interval is not yet a uniquely runnable algorithm from the available description**. Filling in its missing choices ourselves would create a particular proposed implementation, rather than reproduce a documented one. The corrected-code 83.7% result belongs to the fixed-rate person-bootstrap implementation. The 93.3% pilot belongs to the different exact conditional joint-fit candidate. Neither number is measured coverage for the manuscript's joint fit plus stated aggregate-block bootstrap.

The joint Step 1 was also run on [all 600 saved sampled datasets](POINT_RESULTS.md). Its point estimates average 1.00567 with standard deviation 0.03808; the tested fixed-rate code averages 1.00986 with standard deviation 0.01058 on those same datasets. This paired point analysis does not use or validate any bootstrap interval. [BLOCK_BOOTSTRAP_GAP.md](BLOCK_BOOTSTRAP_GAP.md) lists the missing interval details precisely.

## Current disposition

The paper's joint Step 1 passes the exact-population check in this one-window scenario. Pairing its fit with the current software's person resampling gives coverage compatible with nominal 95% here; pairing it with the chosen broad-pool aggregate-block rule fails sharply because the block distribution is shifted. Objection 3 against the **manuscript's intended interval** remains a reproducibility and calibration question: specify the source-time placement, block length, risk-set seam, and diagnostic acceptance rules, identify the generating revision behind any reported intervals, and test coverage for exactly those rules. The 19% number does not establish that every possible implementation of the manuscript outline undercovers, and the 94.5% number does not validate every setting or the fixed-rate production fitter.
