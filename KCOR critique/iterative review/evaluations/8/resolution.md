# Round 8 independent resolution review of KCOR, m135 against m128

> Please examine KCOR closely. What is wrong, if anything, and how would you fix it?

Six of the eleven round 7 objections are resolved within their stated scope. Five are partly resolved. The main implementation gaps are incomplete source histories and loss of the ordinary pooled trajectory. Two small ordinary-workbook examples still produce a finite estimate labeled `ok` after known positive-risk observations disappear. The main scientific reporting gap is consistency. The Czech example now gives specific diagnostic results, but the reporting rule, the definition of a fitting week, and the explanation of which estimand can be biased still differ between sections. The ordinary workbook omits its pooled result for the Table 8 reporting date, and the documented Table 8 refit command reads complete checkpoints. The dedicated archived Table 8 points and percentile arithmetic checked out.

The proportional gamma inversion itself is sound under the stated model. If mean-one gamma frailty has variance θ and the reference cumulative hazard is B, marginal survival is (1 + θB) to the power −1/θ. Hence the reference cumulative hazard is expm1(θH)/θ for observed cumulative hazard H, with limit H at zero variance. Fixing a Gompertz slope supplies identifying structure for the quiet hazards. An unrestricted baseline could absorb a different choice of θ. These are model-conditional descriptive quantities.

## Remaining diagnostic policy wording

The practical guideline in §4.4 says contrasts are not reported if diagnostics fail. §2.1.2 also gives an unrestricted non-reporting statement. SI S2 permits flagged numerical output for audit and withholds substantive interpretation. Its table adds a literal reversal. Under the heading “Consequence if violated”, row I1 gives “KCOR interpretable” when “All required diagnostics pass” is violated. Row I7 instead describes failure in the condition column and gives the consequence of that condition holding.

Use a consistent condition and consequence throughout. Mark a failed identification requirement as preventing substantive interpretation, allow a labeled diagnostic result where the computation is defined, and keep an undefined computation unavailable. A single exploratory residual flag has no automatic rejection threshold. This wording requires no new rejection rule and does not change any S6 estimates.

## Additional workbook defect in the pooled trajectory

The ordinary workbook calculates the contributions for each date inside `for dt in all_dates` in `code/KCOR.py:4784`, but the condition that creates the pooled result (line 4826) and the append to `pooled_rows` (line 4963) are outside that loop. A new set of contributions replaces the previous one on every iteration. Only the final date reaches the row-creation code. The same indentation is present in m128.

In a fresh module-off run of `process_workbook` with `KCOR_BOOTSTRAP_LAYOUT=table8` on the archived 2021_24 input, each of the four direct groups produced 522 rows (174 dates × three dose pairs). The weighted pool produced just three rows, all for October 7, 2024. There was no weighted pooled row for December 26, 2022, the published evaluation date, even though each subgroup has its three finite comparisons on that exact date. The reporting branch at lines 8589–8599 can add the nearest pooled date to a report headed with the selected regular-row date. This can mix different dates in a single display. The production verification script in `analysis/solver_scaling/check_workbook.py` manually recombines the three subgroup values, so it establishes their numerical agreement after pooling but never asserts that the workbook actually exports a pooled row for the date.

Produce the pooled row within the date loop and make any deliberate unavailable rows explicit at their correct dates. Use the requested report date consistently for the pool. Verify the exported weekly trajectory against an independent weighted calculation on the actual workbook and compare a point, intervals and contributing-fit flags at the specified Table 8 date. The dedicated Table 8 replay calculates its own weighted endpoint and is unaffected by this output-loop error. This is independent of the repaired overlap in the direct all-ages row.

## Additional reproducibility defect in the published Table 8 command

The first paragraph of `analysis/README.md` says `python analysis/solver_scaling/table8_replay.py --mode both --draws 999` refits the 999 draws. In m135 each shipped `*-partial.npz` has all 2,000 completion flags set (two enrollments, original plus 999 draws). Lines 36–42 of the runner validate only the shape, load those flags and put only unfinished tasks into the job list. Its documented command therefore submits **zero fit jobs** on this checkout and rewrites the summaries from cached values. A different draw count using the same files fails the shape assertion. An unchanged draw count can reuse obsolete values if the input, fitter, or configuration changes.

Make fresh calculation explicit in the intended reproduction command, add an opt-in resume path with matching input, settings, and estimator provenance, and provide a separate archive-verification mode. An interim documentation correction could instruct users to run in a scratch copy with the two partial checkpoints moved aside. The stored primary and forced-alpha point estimates and percentile arithmetic checked out. This finding concerns independent regeneration, and supplies no evidence that those stored numbers are wrong.

## Scope and limits

I reviewed the frozen m135 manuscript, supplement, code and archives against m128 and the round 7 records. The m135 scientific PDF and approved 7.11 clean PDF have identical SHA-256 hashes. I ran the candidate's ordinary workbook regressions, written-workbook two-draw failure regression, solver grid and S8 verifier, and used scratch scripts for the additional calendar, provenance, figure and interval checks. I did not rerun any full simulation or bootstrap study and did not use current-round blind reviews. Table 8 and S6 percentile evidence here is based on stored draws and reported fits unless a fresh test is expressly identified.

Retaining early anchors, the historical control populations, flagged descriptive outputs, and optional fixed-alpha sensitivities are defensible design choices when named accurately. Dependence on the frailty law and baseline, imperfect low-information coverage, uncertain weekly wave attribution, and the future-product eligibility rule remain limits on interpretation. None of the checks turns the Czech comparisons into causal intervention effects.
