**I would recommend major revision.** KCOR has a valid mathematical core. Given a cohort’s gamma frailty variance, its inversion recovers the baseline cumulative hazard under the stated multiplicative model. The difficult step is learning that variance from mortality data. The manuscript overstates what curvature identifies, the production code fits a different estimator from the one described, and several headline validations bypass the disputed estimation step. The evidence supports using KCOR as a model-dependent descriptive sensitivity analysis. It does not yet establish that KCOR reliably removes selection-induced depletion in the Czech cohorts. ### 1. The identification claim needs a mathematical correction

For any observed cumulative hazard \(H(t)\) and any candidate \(\theta>0\), the baseline \(B_\theta(t)=(e^{\theta H(t)}-1)/\theta\) reproduces exactly the same observed curve. The \(\theta=0\) solution has \(B_0=H\). Thus the observed deaths alone cannot distinguish frailty depletion from a changing baseline. A quiet-period **restriction on the baseline** supplies the identifying information. A good fit to the curve used to estimate \(\theta\) cannot independently verify that restriction. The discussion partly acknowledges this, but the identification proposition and abstract go further. [Inversion](C:/Users/jasmi/AppData/Local/Temp/kcor-s4-approved/m17/documentation/preprint/paper.md:304) · [Identification proposition](C:/Users/jasmi/AppData/Local/Temp/kcor-s4-approved/m17/documentation/preprint/paper.md:345) · [Discussion](C:/Users/jasmi/AppData/Local/Temp/kcor-s4-approved/m17/documentation/preprint/paper.md:947)

There is a direct correction even within the exact Gompertz–gamma model. Write \(h=H'_{\rm obs}\). In a quiet interval with known Gompertz slope \(\gamma\), the paper’s equations imply \(h'=\gamma h-\theta h^2\). Consequently, a **constant observed hazard** can identify positive \(\theta=\gamma/h\), while \(\theta=0\) can produce a curved cumulative hazard through Gompertz growth alone. The claimed equivalence between nonzero curvature and positive frailty is false. Also, multiplying the *observed* hazard by \(c\) changes the implied variance to \(\theta/c\). A common scale factor can cancel in a cohort ratio while changing both fitted variances. **Fix:** replace the proposition with the conditional identification result, distinguish individual-hazard scaling from observed-hazard scaling, and show how the fitted contrast varies over plausible baseline slopes and shapes. Assess prediction on quiet windows withheld from fitting. [Hazard relation](C:/Users/jasmi/AppData/Local/Temp/kcor-s4-approved/m17/documentation/preprint/paper.md:311) · [Gompertz model and scale claim](C:/Users/jasmi/AppData/Local/Temp/kcor-s4-approved/m17/documentation/preprint/paper.md:323)

### 2. The executable estimator differs from the published one

The manuscript jointly estimates \(k,\theta\) in the nearest quiet window. Production code fixes \(k\) to the mean of \(h(t)e^{-\gamma t}\) in the early anchor weeks, fits only \(\theta\) in the first quiet window, and includes anchor weeks in the pooled fit even when they fall outside the quiet windows. Early mortality selection can therefore affect every subsequent normalized value through the fixed \(k\). There is also a discrete-time inconsistency. For a weekly observed integrated hazard \(q\), the exact baseline increment implied by the final inversion is \((1+\theta B_{\rm prev})\operatorname{expm1}(\theta q)/\theta\). The reconstruction used to estimate wave offsets substitutes \(q\) for \(\operatorname{expm1}(\theta q)/\theta\). **Fix:** select one estimator, use the same exact weekly transition in fitting and inversion, and regenerate the results from that implementation. [Published seed fit](C:/Users/jasmi/AppData/Local/Temp/kcor-s4-approved/m17/documentation/preprint/paper.md:371) · [Production anchor](C:/Users/jasmi/AppData/Local/Temp/kcor-s4-approved/m17/code/KCOR.py:1226) · [Fixed-\(k\) seed](C:/Users/jasmi/AppData/Local/Temp/kcor-s4-approved/m17/code/KCOR.py:1375) · [Weekly reconstruction](C:/Users/jasmi/AppData/Local/Temp/kcor-s4-approved/m17/code/KCOR.py:1449) · [Pooled refit](C:/Users/jasmi/AppData/Local/Temp/kcor-s4-approved/m17/code/KCOR.py:1540)

The reporting rule matters just as much. The paper says to withhold normalized contrasts when identification fails. The code can return `success=True, theta=0` for insufficient deaths or a nonpositive first-pass offset. Missing and failed fits can also proceed to inversion with zero. In the Czech run, the log explicitly records a bad fit for the 1980 birth group, dose 2, with zero applied. That turns “unable to estimate the correction” into a numerical identity correction. **Fix:** distinguish an estimated zero with a tight upper bound from an uninformative fit. Propagate failure to the comparison if either cohort fails, and show the observed contrast separately. ### 4. The advertised 95% intervals lack a valid calibration demonstration

The paper describes a contiguous time-block bootstrap with refitting. The workbook path constructs log-normal intervals from death-count variances and post-anchor increments. The coverage script instead draws weekly Poisson deaths around the observed counts, and defines “truth” by applying an estimator to **one reference realization**. Its gamma generator uses deterministic expected deaths, so changing the outer simulation seed does not generate new gamma mortality datasets. The stored run has 500 datasets and 200 bootstrap draws and reports 100% coverage in four scenarios and 25.4% for non-gamma frailty. Those numbers cannot establish coverage of the published production estimator. ### 5. The Czech wave correction and contamination conclusions need narrowing

The paper concludes that the Czech data fail to identify the wave exponent \(\alpha\). The supplied Czech configuration nevertheless forces **1.18**, and the run log confirms that it changes some trajectories. There is also a mathematical error in the stated survivor moment. Under the core gamma model, take initial variance \(\theta=1\) and baseline cumulative hazard \(B=1\). Surviving frailty is exponential with rate 2, so \(E[Z^2\mid\mathrm{alive}]=0.5\). At those same inputs, the code propagates a parameter of 0.5 and evaluates the second moment of a **mean-one** gamma, giving **1.5**. Dividing cumulative wave excess by today’s factor also differs from correcting each weekly excess by the factor applying that week. **Fix:** make the uncorrected run primary, label the forced run as sensitivity only, and derive the survivor distribution and weekly correction under an explicit wave model before interpreting it. Finally, the claimed **66% of baseline mortality** threshold for an apparent harmful contrast is not an empirical bound for the Czech cohorts. Even at **zero contamination**, the two stored null runs have mean anchored KCOR **1.063** and **1.034**, with **14/20** and **15/20** replicates above one. Counting estimates above one under a null measures which side of the null they fell on. It does not measure false evidence of harm. The configuration also says 2023 was chosen because it showed the least vaccine harm, which calls for an outcome-independent replication of the quiet-window choice. **Fix:** compare each perturbation with its paired uncontaminated run, prespecify a meaningful deviation or interval-based decision, and test the chosen windows on held-out data. I would retain the fixed-cohort observed survival curves and the gamma inversion. I would publish observed absolute mortality alongside the unanchored and anchored KCOR curves, with the post-skip population and subsequent dose crossover explicit. Anchoring makes a persistent twofold baseline contrast appear flat at one just as it does an equal-risk contrast.
