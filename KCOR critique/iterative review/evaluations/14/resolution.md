## Remaining related issues and regressions

1. **A failed reference now labels valid unanchored intervals as having fit flags.** This newly visible consequence of the 13.6 repair affects interpretation of the restored rows. In the same 85-week workbook with exhaustion in week index 60, I changed only the reference between indices 59 and 60. At index 59 the unanchored point, limits and 3/3 valid draws were identical. With reference 59 the workbook reported `person_bootstrap_percentile`, zero flagged draws and an unflagged point. With reference 60 it reported `person_bootstrap_with_fit_flags`, three flagged draws and a flagged point. Both cohort fits were `OK` and the residual screen was clear in both cases. In `code/KCOR.py`, `_flag_unavailable_normalization` sets row-wide abnormal status for the unavailable anchored series. In `code/bootstrap_reporting.py`, `attach` reuses that status for the unanchored interval. Track support and flags for each contrast separately. The same test should produce identical unanchored method and flag fields under either reference while preserving the anchored failure.

2. **An unrecognized population layout can bypass the new future-year check.** With the exact documented `disjoint` spelling, the 2099 fixture is rejected. With `KCOR_BOOTSTRAP_LAYOUT=Disjoint`, the ordinary point path still uses disjoint aggregation and skips the birth-year validation. Adding the impossible group changed the all-ages result from 1.000000 to 1.981297, with anchor and normalization both reported as OK. The bootstrap code separately rejects unknown layouts. Validate the layout once before point or interval calculation. This example uses an invalid setting and does not affect the published Czech data.

3. **The normal contamination run can give a reader a different uncertainty bar and still calls the endpoint an asymptote.** The revised plotter reads the archived mean interval when supplied. The simulator's own `sweep_mode` returns standard deviations without `lower95` or `upper95`, so its normal `main` path draws a standard deviation instead. I passed the saved ordinary aggregate and the publication's historical grid separately through the same m169 plotter. At zero dynamic contamination the half-widths were 0.138982 and 0.065045, respectively. Only the historical-grid route matched the published KCOR figure. Preserve the historical grid, give it an explicit plotting entry point, and calculate or clearly label the default run's bars. The generator's user-facing `print_summary` still prints “mean KCOR asymptote” in three branches. Also, the implementation searches backward for the last eligible week, which can precede the final scheduled week. A three-value input ending in an unavailable estimate returned the preceding 1.125. “Last eligible week of 130” precisely describes the implemented rule. These are remaining generator/reporting discrepancies. Neither changes the original paper's plotted results.

4. **The distributed TeX and PDF give different accounts of the same experiment.** Candidate `documentation/preprint/paper.tex`, a named `make paper` output, is byte-identical to the m167 copy. It still calls the contamination endpoint an asymptote and omits the benefit audit-only interpretation. The m169 PDF contains the revised wording, as do its Markdown sources. This older generated artifact already lagged preceding revisions. Regenerate the distributed TeX from the same sources used for the review PDF, or explicitly identify it as a historical artifact.

5. **The new S6 draw archive encodes missing offsets using nonstandard JSON.** The per-dose gap cells are serialized with Python's default `json.dumps`. In 349 dose-draw cells across 345 rows, the encoded array contains literal `NaN`, for example `[[48.0, NaN], [97.0, NaN], [141.0, NaN]]`. A strict JSON reader rejects those cells. The Python reader successfully reconstructed all 42 reported diagnostic rows. Encode missing offsets as JSON `null` with strict serialization and continue mapping missing values to the existing unassessed status. This newly introduced interoperability defect leaves the published interval values intact.
