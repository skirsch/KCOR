### 2. A zero wave offset can erase genuine frailty

The fitter treats **any nonpositive first-pass gap offset** as insufficient signal and returns an applied frailty variance of zero. Yet an interval with no wave has a true offset of zero for *every* frailty variance. The offset measures excess hazard accumulated across the gap. Its sign does not establish whether the cohort was heterogeneous. [Offset definition](C:/Users/jasmi/AppData/Local/Temp/kcor-s3-8d29/m83/documentation/preprint/paper.md:409) · [Sign check and zero fallback](C:/Users/jasmi/AppData/Local/Temp/kcor-s3-8d29/m83/code/KCOR.py:1474)

I tested the current joint fitter on 100 exact model-generated weekly increments with \(k=0.001\), \(\gamma=0.085/52\), true \(\theta=4\), no wave, and quiet weeks 0–27 and 55–89. The seed recovered **4.000000000000019**. The reconstructed offset was **−6.94×10⁻¹⁸**. The fitter returned **\(\theta=0\)** with `success=True` and `status="insufficient_signal"`. This is a reproducible estimator failure with no sampling noise or model misspecification. I would allow a zero offset while retaining the fitted frailty, give offsets a numerical tolerance and a sampling-uncertainty assessment, and propagate genuine identification failures explicitly. This example belongs in the regression tests. ### 5. The wave correction has a better boundary rule, but its input remains biased

The revision fixes how the first modeled wave week enters the reference path and explicitly describes the in-wave calculation as approximate. The new post-wave test checks a valid conditional statement: **given** the exit exposure supplied by the correction, the tail solver recovers a known subsequent baseline increment. The test obtains its wave exposure from the function being tested. It therefore leaves the accuracy of that exposure open. [Revised method](C:/Users/jasmi/AppData/Local/Temp/kcor-s3-8d29/m83/documentation/preprint/paper.md:574) · [Tail test](C:/Users/jasmi/AppData/Local/Temp/kcor-s3-8d29/m83/test/test_nph_post_window_continuity.py:32)

I checked the full path using exact survival under the manuscript’s model, known parameters, exponential frailty of mean one, \(k=0.01\), \(\gamma=0.002\) per week and \(\alpha=1.18\). For a 30-week accumulation of true wave exposure **0.1500**, the code attributed **0.1420**. With **zero** true wave exposure it still attributed **0.000306**. The latter discrepancy has a specific cause: the fitter uses the exact weekly Gompertz integral, while the wave reference accumulates the start-of-week hazard. For positive \(\gamma\), that reference is systematically low. There is also a larger structural approximation: the code divides cumulative excess by a current mean-one gamma moment even though survival through a nonlinear wave changes the frailty distribution.
