# Independent review of KCOR, candidate m156

The proportional gamma inversion and the fixed-slope identification proposition in §2.4.4 are consistent with the stated model. The empirical results support a descriptive analysis. In particular, the age-shift comparisons have no known numerical target, and the residual screen flagged a contributing fit in every primary Table 8 draw. The following problems remain.

### 1. High priority — The all-ages estimate changes when a redundant total is supplied

The default year filter removes unknown birth years (code/KCOR.py lines 271, 703 and 6361). If an explicit all-ages row is present, that row survives the filter with the unknown people included. If the same total needs reconstruction, the unknown people are already gone when the aggregate is formed (lines 4285–4293 and 7467–7496). Restricting the ages displayed separately therefore changes the population behind the same “All Ages” label depending on the file layout. The same inconsistency can apply to known ages outside the display range.

I ran the ordinary workbook on two equivalent 18-week death-only files with birth-year groups 1950 and unknown, two dose groups, and one million people per group. The second file added the exact sum of the source rows as year −2. With the default year range, the endpoint all-ages observed numerator cumulative hazard changed from 0.057140 to 0.112705, and anchored KCOR changed from 1.177097 to 1.165209. Both runs reported numerical success. The published S6 all-ages calculations use supplied totals, so this example does not change those numbers. Build and validate the eligible all-ages population before filtering age-specific output. If a restriction is intended to apply to the aggregate, enforce it identically in both layouts. Test that supplying the redundant total leaves the estimate and bootstrap population invariant.

### 2. Moderate — A pooled KCOR silently saturates at one million or one millionth

The pooled estimator in §2.8 is a weighted geometric mean. In the ordinary workbook, code/KCOR.py lines 4825–4847 applies safe_exp to the weighted log estimate. The helper at lines 905–909 clips its argument at ±log(10⁶), far inside the representable range. A geometric mean over exactly one stratum must equal that stratum.

I ran the ordinary estimator on one birth-year stratum, two initially identical 1,000,000-person cohorts, 32 weekly bins, baseline rate 0.006, gamma variance 5, and a 99% death probability in the numerator in the final, post-quiet week. The fitted variance was 4.999298 and the final risk set was positive. Direct anchored KCOR was 2.043049 × 10¹⁰. The sole-contributor pooled KCOR was 1.000000 × 10⁶ with complete composition and OK normalization. This is a stress case demonstrating an identity failure. Use ordinary exponentiation of the weighted log where representable and report a numerical-range failure otherwise. Use a logarithm without an arbitrary floor for positive finite inputs.

### 3. Moderate — Ordinary bootstrap output discards residual-screen flags

The standalone Table 8 analysis correctly separates numerical failure from residual discrepancy. The ordinary bootstrap cannot give the same distinction. The sampling flag is retained in the parameter dictionary and diagnostic worksheet (code/KCOR.py lines 5570 and 6862), but the contrast rows use an older slope-fit flag and numerical theta status (lines 4520–4558). bootstrap_reporting.flagged at lines 160–174 consequently sees no residual flag. The return-to-worker path transmits gap information only (code/KCOR.py lines 8154–8161). Thus even the number of draws with a contributing residual flag cannot be recovered from the ordinary bootstrap output, despite §2.9.1's description of fit flags being counted across draws.

In the 18-week test above, the 1950 dose-2 fit and the all-ages dose-2 fit both had sampling_flag=True and numerical status OK. The contrast-row classification used for CI_point_flagged and CI_flagged_draws was false for all direct and pooled rows. This changes the diagnostic reporting, not the underlying percentile arithmetic. Retain a separate residual-screen point flag, draw count and unavailable count for direct comparisons and the actual positive-weight contributors to each pool. Preserve numerical status and retain all draws.

### 4. Moderate — An accepted spelling of the enrollment sheet disables every interval

The ordinary point estimator accepts both 2023_19 and 2023-19. Its parser and dose-configuration lookup explicitly support both spellings (code/KCOR.py lines 4255–4276 and 2097–2109). The bootstrap independently uses sheet.split("_") (code/bootstrap_reporting.py line 26). On the same valid history, histories(frame,"2023_19","disjoint") succeeded, while histories(frame,"2023-19","disjoint") raised a ValueError converting "2023-19" to an integer. The caller catches this error and leaves that enrollment's intervals unavailable (lines 247–256). Use a shared enrollment parser in both paths and verify that renaming the worksheet preserves the result.

### 5. Moderate scope correction — A first nonfatal event needs explicit treatment of death before the event

Sections 1.1 and 5 extend the method to hospitalization or disease onset and suggest the additional considerations primarily concern interpretation (paper.md lines 23 and 936). First hospitalization resolves recurrence, but death before hospitalization removes a person from the event-free risk set. Section 2.3 subtracts only the failures being analyzed. For example, if one of two people dies before the second person is hospitalized, the stated risk recursion still counts two people at risk for the hospitalization. Keeping the dead person in the denominator gives an incidence-based quantity with a different interpretation. Removing deaths changes the risk-set law and can select survivors by the same latent frailty. The gamma inversion for a single failure process does not by itself handle this.

Restrict the applicability claim to settings satisfying the displayed single-event survival law. For nonfatal outcomes, state the competing-event estimand and the additional assumptions or joint model needed. The Czech all-cause calculations do not require a change.

### Smaller corrections

- **Pooled frailty labels.** The pooled workbook row copies theta_num and theta_den from the first contributing age (code/KCOR.py lines 4853–4875 and 4904–4914). No pooled frailty was estimated for this geometric mean. Leave those parameter cells empty or label them with their actual source stratum. Keep the aggregate fitted frailty on the separately fitted −2 row.
- **Nonlinear deficit reporting.** Section 2.7.3 asks for deficit-week frequency. The correction computes deficit_weeks separately from skipped_nonpositive_excess (code/kcor_survivor.py lines 171–195), but the workbook logs only the second measure (code/KCOR.py lines 7833–7843). A week exactly consistent with baseline has zero added exposure and is not a deficit. Export the existing strict-deficit count and number of modeled weeks per cohort.
- **Cox comparison.** The tables say Cox and shared-frailty Cox have no interpretable output under non-PH and label a marginal departure a “biased HR” without naming its target (paper.md lines 1091 and 1100). The paper's own shared-frailty description and §2.11 correctly distinguish conditional and marginal hazards. Conditional proportionality can coexist with marginal nonproportionality, and the magnitude of a constant-coefficient working summary under non-PH depends on the event-time and follow-up distribution. Qualify the rows and identify the fixed-frailty benchmark for the displayed departure.
- **Joint simulation documentation.** SI S4.6 says its parameter values and scripts are in the summary table (supplement.md line 242). Its entry at line 163 names only “Frailty heterogeneity plus injected effect.” S4.6 ends with the individual-hazard equation and gives neither results nor a runner. The separately documented S4.3 control injects an effect on the survivor hazard, a different generation mechanism. Provide the actual configuration, script and results for S4.6, or label it as a proposed design.

The numerical checks used the candidate's ordinary process_workbook and bootstrap history reader, with small generated inputs and temporary outputs. I did not modify the candidate or rerun the large validation studies.
